# 任务级评测协议

本目录是一套**待执行的人工评测计划**，不是已测得的模型准确率。自动回归另见tests/。

## 执行方法

1. 固定模型版本/ID、端点、提示词、资料版本、任务题面及程序提交SHA。
2. 用cases.json中的任务建立输入资料。标注“合成”的数据仅测试边界，不能当真实公司业绩。
3. 每个模型任务运行3次，分别保存完整执行JSON。不要只挑最好的一次。
4. 两名审阅者独立核对关键数值、语义支持与信息缺口，分歧人工复核；无第二人时记录单人审阅限制。
5. 与离线流程和人工任务基线分别对比，不把离线规则的确定性结果当模型表现。

## 指标

|指标|口径|
|---|---|
|任务完成率|满足该题全部必须条件的运行次数 / 全部运行次数；系统错误和预算耗尽也计入分母|
|数值准确率|正确的可核验数字项 / 所有生成的可核验数字项；同时记录本应输出但遗漏的数字|
|证据支持率|被引用内容充分支持的事实/计算结论条数 / 需要证据的结论条数；不能只数引用ID|
|缺口处理|缺失、负基数、口径冲突题是否明确处理，不捏造补齐|
|工具选择|是否调用必要工具、是否多余重复、错误后是否合理修正|
|成本与体验|每次耗时、实际报告的token、reported_calls、人工改动次数；无价格时费用留空|

可用报告列：case_id、run_id、commit、model、data_version、status、task_pass、numeric_correct、numeric_total、citation_supported、citation_required、elapsed_seconds、prompt_tokens、completion_tokens、reported_calls、review_notes。

当前程序自动验证引用ID存在，不自动给出上述人工语义评分。任何“准确率”“节省时间”“用户留存”必须由实际评测和用户数据支持。
