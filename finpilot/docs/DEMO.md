# 三分钟演示与面试讲解

## 演示前

从finpilot目录运行`python server.py`，打开本地8510端口。先演示无需密钥的模式；如需展示自主选择工具，需提前配置真实模型并跑完人工验收。

## 演示路线

1. **资料与口径，约30秒。** 载入Apple公开样例，说明是FY2023和FY2024的固定历史值，来源为官方报表，未自动联网。强调全年GAAP值、百万美元、公司财年。
2. **计算与证据，约50秒。** 运行“分析Apple的营收、利润和经营现金流变化”。展示营收同比+2.02%、净利润−3.36%、经营现金流+6.98%。点击引用查看原始数据与来源。
3. **执行记录，约30秒。** 切换执行记录，查看list_companies和calculate_metrics的参数与真实返回。解释离线流程是基线；模型模式才允许按结果选择补查工具。
4. **动态行动，约40秒。** 已配置模型时，询问“利润变化的原因是什么，有哪些证据缺口”。当前样例没有原文，正确行为是承认无法仅凭三个数值确认原因。联合上传CSV与对应原文后再试，并观察是否实际发生search_documents调用；不要预先声称模型一定按某顺序执行。
5. **变化与交付，约30秒。** 保存快照，展示重新导入后比较的入口；导出Markdown及完整JSON，用于复核。说明跟踪是手动更新，自动订阅属于后续迭代。

## 能讲清楚的四个取舍

- 为什么先做这一个场景：资料、计算与引用有清晰验收标准，适合作为最小闭环。
- 为什么计算不用模型：指标程序化计算更容易复核；模型负责选择工具和解释，模型文本仍需校对。
- 为什么没有堆多个Agent：四个只读工具已覆盖基础任务，先测单Agent是否足够，再用失败证据决定是否增加复杂度。
- 为什么把引用存在与可信度分开：存在的引用仍可能不支持结论，需要人工或独立评测验证语义关系。
