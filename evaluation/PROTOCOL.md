# 评测协议

先区分工具、模型、用户三个层面。工具回归为已测；真实模型与用户效果为待测。

1. 工具层：固定数据和gold，不依赖待测函数生成gold。数值容差1e-8；路由比较枚举、窗口；缺失和非法输入应拒绝。完整gold与actual在results.json。
2. 模型层：用20条人工评审清单，接API后冻结问题与数据，每种模型/Prompt重复3次。记录输入/输出Token、完整响应、正确性、引用支持与错误类型。
3. 0/1/2评分：0=错误或编造；1=事实正确但不完整；2=事实正确、可追溯且清晰标注假设。事实性错误须单列，不能被平均分掩盖。
4. 幻觉率：含至少一条证据不支持事实的回答数 / 实际审核回答数。拒答另记，不能把大量拒答带来的低幻觉率解释为任务完成能力。
5. 延迟：分别记录工具、模型和端到端P50/P95。当前results.json延迟仅Node工具。
6. 成本：输入Token×当前输入单价 + 输出Token×当前输出单价。未获得用量或价格不填零。
7. 用户层：至少5位目标用户完成相同任务，与个人原流程作对照；记录完成率、时间与误解，不伪造访谈。
8. 迭代：冻结评测集，再改Prompt或工具；保留失败用例，避免只保留通过结果。评测扩充后同时报告旧集与新增集。
