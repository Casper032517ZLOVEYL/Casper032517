# OpsPilot PRD · 1.2

日期2026-10-21。目标：把固定合成漏斗演示推进为能接入真实报表、核对口径并交付分析的小型业务工具。用户假设：日常依赖Excel复盘的运营/门店/销售分析人员。尚未做真实用户访谈或效率收益实验。

## 本次问题与实现

1.1固定要求八字段和同漏斗，只有日期/金额/订单的真实销售表无法导入；日期、币种和列名也常不同。1.2把来源适配与指标计算分开：来源有何字段就开放何指标，绝不构造缺失成本或注册量。

主流程：选择真实文件→确认粒度/日期/币种/口径→字段映射→检查与修复→确认导入→选择时间与指标→核对证据→导出复盘。无需模型也能完成全流程。

|优先级|需求|验收|
|---|---|---|
|P0|真实报表适配|日汇总最少日期+一个指标；订单一行一单，唯一ID计数；中文/自定义字段可映射|
|P0|导入确认|先检查后提交，错误列出源行号；失败保留当前有效数据|
|P0|口径保护|单币种、金额口径和订单状态显式确认；不能从发票推断已支付|
|P0|缺失保护|缺字段为null，缺日默认不补零；重复日默认阻止，重复订单必阻止|
|P0|可追溯计算|真实UCI交易订单/日汇总与独立Decimal核对一致；公式与窗口可见|
|P0|隐私|默认浏览器计算；未映射列丢弃；模型默认关闭，勾选授权后才发送聚合证据|
|P1|自选时间|本期1–90天；比较前一等长窗口，天数冲突拒绝|
|P1|可交付结果|质量JSON、问题CSV、标准CSV、Markdown/JSON报告和渠道明细|
|P1|受控部署|Gunicorn入口有登录、Host、来源、体积及并发限制；真实HTTP验证|
|P1|模型辅助|一次结构化假设，不改工具值，引用失败保留工具结果|

## 适用边界

CSV5MB/20,000行/100列/20分组，XLSX只读首表，无公式。订单明细一行一单；商品行、混币种、退货负值、带时区日志先预处理。字段、日期、补零和过滤的完整规则见DATA_CONTRACT.md。

不包含平台API同步、数据库连接、退款净额、同比、预测、留存、因果、自由执行Agent、多租户SSO和审计。当前为单人/共享账号试点，没有宣称企业生产SLA。

## 关键状态

- 默认：真实公开历史交易，来源/GBP/正向销售口径明确。
- 导入：可修复编码、分隔符、映射或日期格式；检查通过才启用确认。
- 不完整：先明确日×分组缺失；只有完整导出且无业务时用户可授权补零，报告保留数量。
- 不可用指标：按钮禁用并解释缺字段；自然语言查询返回具体缺项。
- 加载：结果绑定本次问题，导出随有效结果开放；切换数据不接受旧请求覆盖新结果。
- 模型：默认关闭；失败不丢失计算；输出是待验证假设。

## 迭代与验收

1. 数据适配：移除强制八字段与漏斗限制，新增字段映射、订单ID去重、状态过滤、编码日期支持。
2. 分析契约：部分字段、币种、日期范围和完整性保护；不引入任意代码执行。
3. 真实证据：从UCI原档提取公开汇总、保留SHA256与转换记录，独立复算。
4. 交付部署：导入质量报告、部署认证入口、CI与真实HTTP冒烟；Docker配置尚未构建测试。
5. 下一轮以5位目标用户的真实任务测完成率、耗时和口径误解；真实模型另评忠实度、费用和延迟，不从工具测试推导模型效果。

本地自动检查：132历史回归+58项JS分析/导入/导出+50项Python检查=240项。额外真实浏览器CSV/XLSX与Gunicorn HTTP联调。质量报告不能检测整段日期或整个渠道是否在源系统遗漏，最终仍须与原平台总数/总金额对账。

## 风险及处理

|风险|控制|剩余风险|
|---|---|---|
|错误粒度、重复导出|一行一单、ID重复阻止；日汇总合并需声明|不相同ID也可能来自重复业务记录，需原平台对账|
|缺日误补零|默认阻止，显式完整性声明、记录补齐数量|不能验证声明是否真实，不能推断整个分组遗漏|
|金额/时区口径错误|单币种、明确gross/paid、日期格式和本地日|不负责自动换汇、净退款或跨时区转换|
|业务信息外发|默认本地，模型开关显式授权，仅发聚合|问题/分组仍可能敏感，用户应先脱敏|
|模型假设误作事实|结构化与引用校验、待验证标注、失败回退|ID有效不证明语义，需人工评审|
|部署访问/资源|登录、可信Host、固定只读工具、限制并发/请求|试点共享账号，公网需HTTPS代理与限流，无租户隔离|
