# OpsPilot 产品需求文档 · 1.1

版本日期：2026-10-21。性质：AI 辅助开发的个人作品 MVP。目标岗位：AI 产品经理、数据产品、产品运营。

## 用户、任务与证据状态

目标用户假设：需要复盘渠道表现、能使用 Excel 但不熟悉 SQL 的运营人员。主要任务是查看指标、找出变化来源、决定下一步验证什么。尚未开展真实用户访谈，也没有已验证的节省时间或业务增长数据。

主任务：上传日渠道漏斗表，提问“最近7天 GMV 为什么下降”，核对窗口、公式、总体变化和渠道贡献，导出结果用于复盘。

## 本版范围与优先级

|优先级|需求|验收标准|
|---|---|---|
|P0|CSV/XLSX 导入|首表、固定8字段；非法输入有提示，不覆盖旧数据|
|P0|8项指标|与独立算例一致；比率按汇总分子/分母计算|
|P0|比较/趋势/排名/口径|时间和公式明确；零分母不输出虚构值|
|P0|日渠道完整性|窗口中缺少任一日渠道组合时拒绝分析|
|P0|范围约束|多个指标、多个时间范围、预测或无数据维度时澄清/拒答|
|P1|按渠道分析|自然语言指定或下拉框选择；冲突时提示|
|P1|报告导出|Markdown、JSON 和明细 CSV 与当前结果一致|
|P1|变化预警|相对变化绝对值≥10%时标注；不声称统计显著|
|P1|可选 AI 假设|每次一次调用；JSON 字段与引用ID校验；失败保留工具结果|
|P1|反馈|当前浏览器最多保存200条；JSON可导出，不自动上传|

不包含：同比、任意指定日期、用户级留存/分群、预测、因果识别、任意代码执行、数据库连接、多用户权限和自动预算执行。

## 数据契约

一行=一个自然日×一个渠道。日期和渠道组成唯一键。必填字段见 [DATA_CONTRACT.md](DATA_CONTRACT.md)。上限5 MB、20,000行、20渠道；无活动须填显式零值，缺失不能当零。曝光≥点击≥注册≥订单必须属于同一个统计漏斗；不适用于新老用户统计口径混杂的报表。

时间以**整份数据最大日期**为锚点。选某渠道后不能把它最后有数据的日期当作新的今天，否则会掩盖该渠道漏数。比较需要两段等长完整窗口；趋势和排名只需要本期，不展示不完整的前期。

## 输出、状态与 AI UX

结果顺序：核心结论 → 趋势/排名 → 渠道明细 → 口径引用 → 下一步验证。事实和待验证假设分开显示。

- 默认：合成数据，直接可以分析。
- 加载：禁用重复提问和导出；完成后恢复。
- 上传失败：说明具体字段或粒度问题，保留上次有效数据。
- 分母零：显示不可计算，不进入有效排名。
- 模型失败或返回非法引用：提示回退，仍保留计算证据。
- 反馈和导出：绑定本次结果，不上传到第三方统计后台。

## 评测与发布门槛

实际已测：132项参数化回归、24项新增分析/导出测试、27项后端与本地模拟 API 测试。数值容差1e-8。通过率不能解释为真实大模型准确率；API模拟不能证明真实服务质量。

待测：真实模型答案的忠实度、引用支持程度、拒答覆盖、实际Token费用、P50/P95网络延迟和5位目标用户的任务完成情况。人工清单见 [HUMAN_EVAL.md](HUMAN_EVAL.md)。

## 本次迭代与取舍

1. 模块拆分：口径、校验、路由、计算、图表、报告和模型接入各自维护。
2. 删除重复模型计划调用：本版有限语言路由已能覆盖指标工具，模型只提供额外假设。
3. 增加范围校验与导出：减少人工复制，并使输出可以复核。
4. 保留轻量关键词知识检索。6条口径无需强行引入向量数据库。

下一阶段先收集真实任务与失败样例，再决定是否引入语义计划器或混合检索，避免仅为增加技术名词扩展架构。
